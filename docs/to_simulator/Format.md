# Unity Simulator WebSocket Protocol Format

This document defines the WebSocket request/response protocol used by Python client code in `src/simulator/api.py` and `src/simulator/red_bot.py`.

## 1. Transport Basics

- Protocol: WebSocket
- Default endpoint: `ws://localhost:8765`
- Interaction mode: single request -> single response
- Message encoding: UTF-8 JSON string

Server requirements:

1. For each received request packet, return exactly one response packet.
2. Response must carry the same `request_id` as the request.
3. Do not return non-JSON text.

## 2. Request Packet Format

Each request is a JSON object with this structure:

```json
{
  "request_id": "<uuid-hex>",
  "timeout": 5000,
  "team": "red",
  "command": "ChassisForwardAction",
  "value": {
    "distance": 1.2
  }
}
```

Field definitions:

- `request_id` (string, required): unique ID generated by Python side.
- `timeout` (int, required): timeout budget in milliseconds.
- `team` (string, required): `red` or `blue`.
- `command` (string, required): action name, must match one command in section 4.
- `value` (object, required): action parameters.
  - Contains command-specific fields if needed.

## 3. Response Packet Format

Common response base:

```json
{
  "request_id": "<same-as-request>",
  "success": true
}
```

Extended response with payload value:

```json
{
  "request_id": "<same-as-request>",
  "success": true,
  "value": 3.5
}
```

Error response (recommended):

```json
{
  "request_id": "<same-as-request>",
  "success": false,
  "value": "error: reason"
}
```

Notes:

1. Python validates `request_id` and `success` first.
2. Some commands require `value` as `float` or `string` (see section 4).
3. For `success=false`, returning a string `value` is recommended for diagnostics.

## 5. Validation Rules (Server Side)

Server should validate and reject invalid requests:

1. Request is valid JSON object.
2. Contains `request_id`, `team`, `command`, `value`.
3. `team` in {`red`, `blue`}.
4. `timeout` exists at top-level and is integer > 0.
5. `command` is known and required params are present.

Recommended invalid-request response:

```json
{
  "request_id": "<request_id-or-empty>",
  "success": false,
  "value": "error: invalid request: <details>"
}
```

## 6. Timeout Semantics

Current protocol assumes one timeout budget per request:

- `timeout` is the budget in milliseconds.
- Server should use this as execution deadline.
- If timed out, server should respond with `success=false` and error message.

Recommended timeout response:

```json
{
  "request_id": "<same-as-request>",
  "success": false,
  "value": "error: timeout"
}
```
